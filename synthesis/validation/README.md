# What was actually regenerated

These are new same-owner export-validation runs on Linux/aarch64, Python 3.12.3,
NumPy 2.5.2, SciPy 1.18.1, CasADi 3.8.1, MuJoCo 3.3.5 and mpmath 1.3.0, with
one BLAS/OMP thread. They do not alter original frozen evidence or consume a
reserved label. Original validation JSON hashes and public portable receipts
are listed in [summary.json](summary.json). Native binaries were not certified
against the historical runtime closure; actual outcomes are reported directly.

The validation rebuilt both derivative providers from the exported Python
mechanics and local C compiler. All selected reference Jacobians matched the
original-provider numeric checkpoint byte for byte. Both 100-digit upright
designs also regenerated their original arrays exactly.

The following selected construction stages reproduced all compared array bytes:

- Fifteen's 650-command repaired reference from the hash-checked public warm
  input; its original recorded 700-command physical-reference extraction;
  an independent native replay of those 700 delivered controls from exact
  hanging; and its selected prototype, gain/value/parking arrays and payload.
- Sixteen's fourteen-donor material lift, 700-command base repair, three-frequency
  orbit screen/selected five-hertz orbit, actual 800-command exact-hanging
  parking prefix, early-bend bridge, native parking-cost screen, original
  probe07 feedback payload and selected 650-entry prefix.

The short reconstruction independently regenerated every selected fifteen
feedback/value array and every selected sixteen array. New exact-hanging
diagnostics from those rebuilt payloads completed all 1,500 commands: fifteen
held for **8.18 s**, sixteen for **7.34 s**. Cold native replay checked every
command of each new diagnostic with **zero maximum dynamics defect**.
The selected payload container hashes also match the published controllers:
fifteen `8514b50a…`, sixteen `de5afbb5…`.

## Known limit: the earlier fifteen native-value episode

`15-first-native-pass`, run with the preserved final worker and regenerated
repaired reference, succeeds for the complete thirty seconds and earns the same
24.18-second hold as the original. Its feedback/value arrays match the original
first-native controller exactly. **Its complete physical tape does not match
the historical tape byte for byte:** actions first differ at zero-based command
index 489 and states at index 490. Maximum state difference is approximately
`3.0414e-5`; maximum normalized delivered-command difference is `6.9460e-6`.

The cause of that action-selection difference is not isolated. The earlier
full live-worker revision/argv was not retained alongside that receipt, and
package-version equality does not establish an identical native runtime.
The published reconstruction therefore does not claim exact recovery of that
earlier online decision process. Its fresh tape and comparison remain negative
for byte identity, even though the task passes.

The exact historical physical-reference checkpoint is included. The optional
`15-physical-reference --replay-native` reconstructs it exactly by native replay
of the retained original command prefix from exact hanging. That is a disclosed
recorded-control replay, not a newly reproduced closed-loop selection result.
This checkpoint is the reliable starting point for exact selected fifteen
feedback regeneration. Propagating a freshly different earlier tape is a new
design attempt and is reported as different.

## Reading solver outcomes

An optimizer exiting zero does not mean its reference is feasible or its
controller passes. The original stage receipts retain solver status, residuals,
bounds and physical outcomes separately. The selected sixteen optimizer
reference has a native cold-map gap near `3.06e-6`; its actual closed-loop
diagnostics pass and replay separately. No feasibility flag is rewritten to
match a controller result. Retained local-orbit tests also remain incomplete
or failed full episodes even when their first five seconds track upright.

Only the short feedback/diagnostic path is repeated in a clean extraction for
publication. The slower stages are tested once with explicit checkpoints, as
recorded here; they are not a new reserved qualification or an external review.
Other platforms have their own array comparisons and diagnostic outcomes.

[Clean-extraction receipts](clean-extraction.json) record the tested candidate
archive and source/numeric hashes. Both feedback and exact-hanging diagnostics
passed with `PYTHONPATH` removed. File-access tracing found no accesses to the
original campaign directories or private Rage Mill worktrees. The final archive
adds these receipts/documentation; its tested code and numeric inputs are
checked against those same hashes. The separate dependency environment was
installed from this export's requirements, not copied from a research runtime.
